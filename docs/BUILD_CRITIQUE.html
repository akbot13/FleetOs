Critique

Verdict: not ready for real customers yet. Ready for a supervised internal trial.

The admin and driver surfaces work end to end against the live database, and the tenant isolation done this week holds (17 of 17 database checks pass). Three holes found during this review let a customer or a driver change money; all three were closed and verified on the live database the same day. The remaining blockers are below.

What is solid

  • Customers book through two server functions and get a private tracking link, so customer data is no longer readable by anyone with the public key.
  • Driver PINs are hashed, never readable, and lock after five wrong tries for 15 minutes.
  • Dispatch ranks drivers by real distance from the pickup and never invents one when GPS is missing. Covered by unit tests.
  • Cash maths (hand-over, net earnings, paise rounding) lives in one tested function.
  • The driver app was split from one 1,900-line file into nine files by job. 34 unused UI components and 27 packages are gone.
  • npm run db:check catches a missing migration on the live database in seconds.

What is weak

  • The database trusts the client with money. The customer's browser sends the fare; drivers can edit any column of their own trips and their own driver record, including approval status.
  • Several screens look real but are not. Customer trip tracking is a static mock, the admin Pricing screen's Save button saves nothing, and customer fares are hard-coded in two files.
  • Nothing protects main. No CI, 57 lint errors, and the end-to-end tests still script the old OTP sign-in, so they fail.
  • Work is not landed. 51 changed files sit uncommitted and the branch is 4 commits ahead of main, which is what Vercel deploys.
  • No one is told anything. SMS and WhatsApp sending is wired to an edge function but no provider is live.
  • DriverApp.tsx is still 887 lines and AdminDashboard.tsx over 1,000.

Blockers

Each blocker stops a paid pilot with real customers. The first three were confirmed by reading the live migrations during this review.

Critical path: H → I → O, 13.3 days

SMS sign-up is the long pole because Indian carriers require DLT registration of the sender and every message template before delivery. Start it on day one; it is mostly waiting, so the developer works the pilot path in parallel.

Confidence

Path variance is 6.36 (σ ≈ 2.5 days). About 86% chance of go-live within 16 working days, 50% within 13.3. If the owner keeps PIN sign-in, task I drops and the pilot path (D → E → F → N → O, 11.5 days) becomes critical.

Project constraints

ConstraintDetailEffect on the plan
PeopleOne developer working with Claude; the fleet owner is the only domain expert and tester.No parallel feature work. Pilot feedback comes through one person.
BudgetNear zero. Supabase free tier (500 MB database, 1 GB storage, 2 GB egress), Ola Maps free tier, Vercel Hobby.Vercel needs the paid Pro plan before charging customers. Photos must be compressed to stay inside 1 GB.
RegulationTRAI DLT rules for SMS; DPDP Act 2023 for phone numbers and live location; GST invoices for fares.SMS is on the critical path. A privacy notice and data-retention rule are needed before go-live.
DevicesDrivers use low-end Android phones on patchy 3G/4G, often outdoors in sun.Bundle size and offline handling matter more than visual polish. Large tap targets.
LanguageTier-2 city drivers and customers; many prefer Hindi.English-only is acceptable for the pilot, not for wider rollout.
ArchitectureBrowser talks to Supabase directly. Every rule must live in database policies or server functions.Any check done only in React is not a check. B1–B3 came from this.
Third partiesOla Maps (5M calls a month free), Nominatim and OSRM public servers as fallback, unpkg for Leaflet.Public fallbacks have usage limits and can rate-limit a busy day.
TenancyOne organisation (Anil Cabs) in production; the schema is multi-tenant but there is no onboarding UI.A second fleet needs manual SQL until FO-20 is done.
Scope decisionsOwner chose admin-set PINs over SMS OTP "for now"; payments deferred.Both stay off the pilot gate; both are on the go-live gate.
ReleaseVercel deploys main automatically; nothing is pushed without the owner's go-ahead.Every merge to main is a production release.
